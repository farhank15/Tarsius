# Coding Style

## General Rules
- Detect the project's primary language from existing files
- Follow the project's existing coding conventions
- Match indentation, naming, and formatting to the codebase
- Preserve existing patterns — don't introduce new styles

## File Naming
- Mirror the project's existing file naming conventions
- Mirror source structure in test files

## Comments
- Use the project's documentation style (JSDoc, docstrings, rustdoc, etc.)
- Use inline comments for complex logic
- Never comment obvious code
