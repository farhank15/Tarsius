How It Works

The Four-Step Workflow

Tarsius runs as a custom Bob mode with dedicated subagents — capturing tacit knowledge before it's gone and persisting it as a binding contract that constrains all future code generation.

1
Capture — Surface What Bob Cannot See
Senior engineers are guided through a structured review session. Tarsius reads both source code and documentation simultaneously, detecting contradictions and surfacing implicit rules that static analysis cannot reach. The interview asks only about genuinely undocumented gaps — not what's already in the code.
Agent Mode Subagents Document Understanding
2
Persist — Outside the Context Window
Approved rules are written to a structured, versioned Business Rule Inventory stored outside Bob's active context window. Every decision is recorded as an immutable hash-chained audit trail — who approved what, when, and why. Zero database required.
Custom MCP Tools BRI JSON Hash Audit Trail
3
Reinforce — Re-inject Before Every Generation
Before any code generation task, approved rules are automatically re-injected into Bob's working context via lifecycle hooks — regardless of session boundaries or context compaction. Bob always has the right knowledge, even three weeks later in a brand new session.
Lifecycle Hooks MCP Resources RISK-CONTEXT.md
4
Learn — Institutional Memory Accumulates
A gotcha memory stores institutional knowledge across sessions — legal exceptions, class action settlements, undocumented workarounds. The system becomes progressively better at flagging dangerous exceptions automatically as more senior engineers are interviewed over time.

Key Features

What Tarsius Adds to IBM Bob 2.0

Bob provides the execution engine. Tarsius provides knowledge capture, persistence, triage, and verification — capabilities that don't exist in Bob natively.

Structured Interview Mode
Guided session surfaces undocumented rules, exceptions, and workarounds that exist nowhere in writing. Captures knowledge that no document, Redbook, or code comment contains.
Deterministic Risk Triage
5-condition classifier with zero LLM calls. Contradictions are always must-review. High-confidence dual-source rules are auto-approved. 50–70% of rules require no human attention at all.
Pre-Generation Binding Contract
RISK-CONTEXT.md is auto-generated after approval. Bob reads this file before generating any code — AI cannot deviate from approved rules, even across sessions.
Context Window Persistence
Rules persist outside the context window in BRI JSON files. Re-injected via lifecycle hooks before every edit — regardless of session boundaries or context compaction events.
Immutable Decision History
Hash-chained audit trail of every approval and rejection. Who decided, when, and why — with a cryptographic chain linking each record to the previous one. Compliance-ready from day one.
Gotcha Memory
Institutional knowledge accumulates automatically over time. "Don't remove the DISC exception — class action CS-4471." Persists forever, across sessions, across team members.
Confidence Badge
After Bob generates code, Tarsius compares output against approved rules via AST diff and heuristic fallback. Catches AI deviations before they reach production — not after.
Contradiction Detection
Cross-references code against documentation automatically. Flags when code and spec disagree — like the DISC exception that was 11 years out of sync with its own specification.
Governance Dashboard
React-based dashboard for reviewing extracted rules, approving or rejecting pending items, exploring code provenance with line-level evidence, and monitoring risk scores in real-time.

Risk Triage System

Must Review
Contradiction detected or low confidence. Always requires human approval before any code generation proceeds.
Glance
Medium confidence or single source only. Requires a quick human sanity check — typically under 30 seconds.
Auto-Approve
High confidence, dual source, no contradiction. Safe for automatic approval — no human needed. 50–70% of rules land here.

MCP Tools

5 Custom Tools Bob Calls at Runtime

Tarsius implements a custom MCP server registered in .bob/mcp.json. Bob calls these tools during extraction, approval, and generation — converting free-form AI output into structured, versioned artifacts.

write_finding()
Records a structured business rule into the BRI with triage classification, confidence score, evidence location, source attribution, and contradiction flag. Converts Bob's free-form extraction output into typed, versioned JSON.
get_pending_approvals()
Returns the list of rules awaiting human review, with optional filters for module, triage level, or contradiction status. Powers the approval queue in the Tarsius Dashboard and Bob's review workflow.
mark_approved()
Approves or rejects a rule after human review. Auto-generates an updated RISK-CONTEXT.md binding contract. Records the decision in the immutable hash-chained audit trail. Bob reads the contract before its next generation task.
record_decision()
Writes an immutable hash-chained decision record containing who decided, the decision, the justification, a risk score snapshot, and a chain hash linking to the previous record. Every record is cryptographically tamper-evident.
check_gotchas()
Cross-references a rule against the institutional knowledge store. Returns matching gotcha warnings such as "Class action CS-4471 — DO NOT remove without legal sign-off." Ensures institutional memory is surfaced before every approval decision.

Get Started

Up and Running in 5 Minutes

Tarsius requires IBM Bob 2.0, Node.js 18+, and npm. No database, no cloud infrastructure — just JSON files and a local MCP server over stdio.

1

Clone the repository

Get the source and navigate into the project directory.

2

Build the MCP server

Compile the TypeScript MCP server. Bob connects to this process over stdio at runtime.

3

Start the dashboard

Launch the React governance dashboard. Opens on localhost:5173 by default.

4

Copy Bob configuration

Copy the .bob/ templates to your project root. This registers custom modes, skills, MCP server, and rules with Bob.

5

Open Bob IDE

Select Legacy Analyzer mode. Attach your RPG source file and spec document. Start the structured interview workflow.

# 1. Clone
git clone https://github.com/farhank15/Tarsius
cd Tarsius

# 2. Build MCP server
cd mcp-server && npm install && npm run build

# 3. Start dashboard
cd ../dashboard && npm install && npm run dev

# 4. Copy Bob config
cp -r templates/.bob .

# 5. Run end-to-end tests
npx tsx test/flow-test.ts
# Expected: 33/33 tests passing

FAQ

Frequently Asked Questions

Common questions from developers, architects, and judges reviewing Tarsius.

Why not use Bob's built-in Business Rules Extraction?
Business Rules Extraction reads logic already encoded in source code. RAG retrieves answers from documentation or Redbooks. Both require the knowledge to already exist somewhere in writing. Tarsius addresses the case neither can reach: knowledge that was never externalized at all — the exceptions that live only in a person's memory. Bob reads what's written. Tarsius captures what's only in someone's head.
What happens when the senior engineer retires?
That is exactly the problem Tarsius solves. The structured interview captures tacit knowledge as a persistent, versioned artifact — Business Rule Inventory, decision history, and gotcha memory. Once captured, the knowledge persists indefinitely regardless of who leaves the organization. The value compounds: the more engineers interviewed before retirement, the richer the institutional memory becomes.
How is this different from traditional documentation?
Traditional documentation is manual, prose-based, and quickly outdated. Tarsius generates structured, timestamped, attributed records automatically — with an immutable audit trail of who approved what and why. And critically, Tarsius captures knowledge that was never documented in the first place. Most documentation captures what should happen; Tarsius captures the exceptions and workarounds that everyone knows but no one ever wrote down.
Does Tarsius add overhead to the review process?
No — it makes review dramatically more efficient. Without Tarsius, a developer reviews 200 lines of generated code looking for subtle deviations (roughly 2 hours). With Tarsius, the developer approves a small set of flagged rules (roughly 5 minutes). 50–70% of rules are auto-approved by the deterministic classifier — developers only see the must-review rules that require human judgment.
How does this work with context compaction?
Bob's context window gets summarized over long sessions, losing detailed history. Tarsius persists rules outside the context window in BRI JSON files and re-injects them via lifecycle hooks before every code generation task — regardless of session boundaries. The approved rules are always present in context when Bob needs them, even in a completely fresh session months later.
How does it scale to 5,000+ legacy programs?
The deterministic triage classifier automatically routes rules by risk level. Developers focus review only on high-risk must-review rules. The system is file-based with zero infrastructure: JSON and Markdown, Git-native, no database, no cloud. It scales with the team's review capacity, not the codebase size. Parallel subagent extraction means multiple modules can be analyzed concurrently.
Is the triage classifier just another LLM score?
No. The classifier uses 5 deterministic conditions — contradiction detected, confidence level, source count, module impact count, rule type — with zero LLM calls. Results are fully reproducible. The same rule always gets the same triage level regardless of context, session, or model state. This makes the system auditable and trustworthy for compliance purposes.
Is this production-ready?
The architecture is production-suitable: Git-native, JSON flat-file storage (no database required), zero external infrastructure. The MCP server is TypeScript with full type safety and a 33-test end-to-end suite validating the complete workflow from extraction through approval and generation. Modernization teams can adopt it immediately with their existing Bob and Git setup.
