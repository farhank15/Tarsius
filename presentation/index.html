The Knowledge Disappearance Crisis

Critical operational knowledge is vanishing from IBM i teams — and existing AI cannot recover what was never written down

Legacy Crisis

The Retirement Wave

72% of RPG developers are over 50 (Fortra 2026). Skills gap = #1 concern (69%), overtaking cybersecurity for the first time in 9 years (Fortra 2026). When they leave, they don't just take syntax knowledge — they take undocumented exceptions, workarounds, and gotchas that were never written anywhere.

Sources: Fortra IBM i Marketplace Survey 2026
Verification Crisis

The Written-Word Blind Spot

IBM Bob reads everything written: repository-wide context over source code, document understanding over specs. But all of it requires knowledge to be already written down. When a critical rule exists only in someone's head, even the best agent silently fails — generating plausible code that violates a rule no one remembered to state.

Sources: IBM Bob documentation, Tarsius analysis
Logic Loss Gap

The Knowledge Gap Is Permanent

Once a senior developer retires without a structured handoff, that knowledge gap becomes permanent and unrecoverable. No future AI tool, however capable, can extract knowledge from a document that was never written. 30-50% cost overruns are common when teams must reverse-engineer intent from code alone.

Sources: Gartner 2026, Industry analysis

Phase 1 · Capture

Structured Interview & Rule Extraction

Subagents scan RPG code and attached spec documents. The interview surfaces implicit rules Bob's static analysis cannot detect — undocumented exceptions, workarounds, and gotchas that exist only in a senior engineer's memory.

Phase 2 · Persist

Knowledge Persistence & Binding Contract

Approved rules are written to a versioned rule ledger (BRI) with immutable audit trail. Tarsius generates RISK-CONTEXT.md — a binding contract that constrains all future AI generation.

Phase 3 · Reinforce & Learn

Context Persistence & Verification

Lifecycle hooks re-inject approved rules before every code generation task — even across session boundaries. BETH catches deviations vector-by-vector. Gotcha memory accumulates.

4 Specialized Subagent Roles Native to IBM Bob 2.0

Capture, persist, reinforce, and learn — orchestrated via Bob's native subagent system

1
rule-extractor-agent

Rule Extractor (Capture)

Scans legacy RPG/COBOL code, extracts implicit & explicit rules, surfaces undocumented exceptions, and writes structured records into BRI JSON via write_finding().

2
contradiction-auditor

Tacit Knowledge Interviewer

Guides senior engineer through structured review, surfaces rules Bob cannot detect. Compares docQuote vs codeLocation to flag contradictions.

3
code-transformer

Code Transformer (Reinforce)

Generates code strictly constrained by approved rules in RISK-CONTEXT.md. Lifecycle hooks ensure rules persist across sessions.

4
beth-verifier

BETH Verifier (Verify)

Runs the BETH differential oracle: 12 ORDVAL vectors against the SME-approved rules. Deviations surface per vector. Decision history + gotcha memory accumulate for future sessions.
